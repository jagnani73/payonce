# MCP server: dated checks

How the rules in [design/mcp-server.md](../design/mcp-server.md) were checked, as written at the time. Only paths have been updated to the current layout, so a note may describe behaviour that has changed since.

## 2026-11-02: every tool against the JSON API, both protocol eras

Checked on 2026-11-02 with a scripted stdio client kept outside the repository, on copies of the main ledger (upgraded once, then a pay run and an outage added through the Ledger's own methods), through `pnpm mcp`: 205 checks passed. Both eras answered: `initialize` with 2025-11-25 and 2024-11-05, and `server/discover` on 2026-07-28. Every tool was called with valid and invalid input. On the same file, every tool's answer equalled `GET /api/board` (five filter sets), `/api/incidents`, each `/api/incidents/:id`, `/api/runs`, `/api/runs/1`, `/api/outages` and `/api/cash/cached` of a real `pnpm ui` started with Airwallex unreachable, where the shapes overlap. `/api/cash/cached` started no balance read, and `/api/cash` still did. A copy seeded with hostile text in 20 fields, and a stand-in server answering with it, showed every seeded string inside `outsideText`, no U+202E or U+200B, no live `https://`, no email text, and phone numbers only as their last four digits, and its audit reported the edited line. The hash, size and mtime of every copy were unchanged, no journal file appeared, the original `payonce.db` was untouched, and the MCP process opened no connection but to 127.0.0.1 on its `PORT`. `claude mcp add` and `claude mcp list` with Claude Code 2.1.316, run in a scratch home and config directory, showed it connected in the modern era (2026-07-28) and with `MCP_PROTOCOL_NEGOTIATION=legacy` (2025-11-25). Claude Desktop was not tried.

## 2026-11-02: outside text in the source of every plain field

Checked again on 2026-11-02 with the same client, extended, on fresh copies outside the repository: 253 checks passed. The hostile copy had text in 29 fields, the sources of every field once plain by its name among them: email evidence naming a sender and a phone number, a needed-approvers reason for an invoice and for a run, a stored findings summary and reader name, countries in an invoice's terms, a run row's estimate and the run's terms, a run's supplier domains, its stored cash check, an outage code with no label, an active outage on a rail that is not a code, and a `RESERVE_FLOORS` PayOnce cannot read. In both eras every seeded string arrived inside `outsideText`, and plain sentences appeared only at the paths in `PLAIN`, with no live link, backtick or full phone number. On the main ledger's copy, approvals 1 and 3's evidence arrived wrapped as `quoted` and today's wording stayed plain. A copy with a hot journal left by a killed writer got the interrupted-write refusal, and neither file changed. A fake `.env` with fake keys gave `RESERVE_FLOORS` from its `export` line, no key reached stdout or stderr, and the file was removed. The missing-ledger refusals named no folder above the PayOnce folder. Every copy and the original `payonce.db` were unchanged.

## 2026-11-02: after the rebase onto main, with every socket and file write logged

Checked on 2026-11-02 after the rebase onto main, with a new stdio client and a preload that logged every socket, DNS lookup, fetch, `parseEnv` input and file write. The check used a copy of the main ledger and a copy with outside text in the sources of every field, the close card's covered transfers included. Two gaps turned up and are fixed: a route, method or due date edited into a stored estimate reached the plain advice and fee line, and the number on file written without its country code passed unmasked in a reference. With both fixed, every seeded string arrived inside `outsideText`. A fake `.env` gave `parseEnv` only its three allowed lines and left no key in `process.env`. A hot journal from a killed writer got the interrupted-write refusal, and opening the file as `pnpm board` does then rolled the write back. The only connections were tsx's local pipe and `127.0.0.1` on `PORT`. No copy changed, and neither did `payonce.db`.

## 2026-11-07: the tools on the typed views

Checked on 2026-11-07, with the replay rig and scripts kept outside the repository:

- Rig run `mcp-views-3` against `base-a33ab93` with `--max 1000000`, classified by `classify.mjs`: only `mcp.json` files differ (instructions, tools/list and tool answers); no other file differs.
- `sweep.mjs` ran every tool (all board groups, both incident states, every invoice, run and record, `waiting_for` for each approver and an unknown name, timelines at 1,000 lines) on the 33 end ledgers of `base-a33ab93`: no refusal, and `report.mjs` found every unlisted non-token string to be PayOnce's words.
- `seed.mjs` wrote outside text into every column that holds it (free text with a live link, a backtick, a phone number and an instruction; valid names; email subjects and typed notes as link-shaped strings in the forms PayOnce's links take) on copies of all 33 ledgers. `scan.mjs` over 933 answers: no marker, link-shaped seed or phone number outside `outsideText`, no `://` or backtick inside it. The link-shaped seeds arrived wrapped as email subjects, close notes, outage end notes, draft dismiss notes, run cancel notes and timeline lines.
- Phones: no answer over `bank-change-callback` or the two real ledger copies holds the number on file, or its last seven digits, in any form.
- `theirs\`: a copy of `src` with `Theirs` branded and `check.ts`, run with the worktree's `tsc`: every `Theirs` path in every view an MCP tool answers is listed with a source. Removing three listed fields made it name exactly those three.
- `watch-preload.mjs` loaded into the MCP process for the whole sweep: every SQLite open was `readOnly=true` through `new Ledger`, the only fetch was `127.0.0.1:<PORT>/api/cash/cached`, the only timer outside tsx was undici's 499 ms tick for that fetch, and no worker, child process or HTTP server was started by PayOnce code.
