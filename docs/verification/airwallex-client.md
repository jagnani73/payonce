# Airwallex client: dated checks

How the rules in [design/airwallex-client.md](../design/airwallex-client.md) were checked, as written at the time. Only paths have been updated to the current layout, so a note may describe behaviour that has changed since.

## 2026-11-07: `redactKey` and spaced keys

2026-11-07: checked with a throwaway script (`<SP>\x1\check.mts`, output in `<SP>\x1\check-output.txt`) on synthetic keys shaped like Airwallex's client id, API key and token, Anthropic's and Gemini's keys. All 34 cases passed. 24 were cut: the key alone, in JSON, in a URL, URL-encoded, base64 inside a Basic header, upper-cased, cut short; split by single spaces, every 4 characters, a newline, CRLF with indent, tabs, zero-width spaces, soft hyphens and NBSP, a Hangul filler, a JSON `\n`, ` `, a URL `%20` and `+`, hyphen groups, spaced and upper-cased, spaced and cut short, mixed with other text, and two separate pieces of the key. 10 near misses were left alone: the first 19 characters spaced, every 15th character changed, another key of the same shape, the `sk-ant-api03` prefix spaced, the key reversed, English text, hex ids, and short keys spaced. Every form the old code cut gives the same text, except where the old code left two labels with only separators between them, which now become one. 204 repo text files (3 MB) with 11 keys each gave 0 differences from the old code. 3,000 random keys (20 to 99 characters) hidden in random text with random separators were all cut, and no text outside a key was cut.
